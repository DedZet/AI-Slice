# ADR-0010: Основной язык - Python, для интерфейса - React

- Статус: Принято
- Дата: 2026-11-12
- Проект: AI-SLICE. Умная нарезка моделей для 3D-печати
- Уточнено: 2026-11-12 (веб-часть переведена на FastAPI и React, см. ADR-0003)

## Контекст

В проекте нужно: считать геометрию модели (ADR-0005), сделать MCP-сервер (ADR-0004), общаться с нейросетью (ADR-0006), запускать OrcaSlicer (ADR-0002) и показать веб-интерфейс (ADR-0003). Языков и библиотек для этого много, а времени мало, поэтому всю серверную часть лучше писать на одном языке.

Для интерфейса в ADR-0003 выбран React, а он работает на JavaScript или TypeScript. Значит, в проекте будет два языка: Python для всей логики и JavaScript/TypeScript только для браузерной части.

## Решение

Серверная часть и вся логика - на Python:

- анализ моделей: библиотеки для работы с сетками и числами (например, trimesh и numpy);
- MCP-сервер: официальная библиотека MCP для Python;
- бэкенд веб-интерфейса: FastAPI (обоснование в ADR-0003);
- запуск OrcaSlicer: как обычной внешней программы из Python, тяжёлые задачи выносим в отдельные процессы.

Интерфейс в браузере - на React (ADR-0003):

- общается с бэкендом только через API FastAPI, логики нарезки и анализа в нём нет;
- готовая сборка отдаётся самим FastAPI, поэтому пользователю Node.js не нужен, он нужен только разработчикам для сборки;
- пишем простой интерфейс без лишних библиотек: форма загрузки и таблица параметров.

Конкретные библиотеки можем поменять, если в процессе окажется, что они не подходят. Менять язык серверной части без нового ADR не будем.

## Рассмотренные варианты

- JavaScript или TypeScript для всего. Есть и MCP-библиотека, и веб, но для работы с 3D-сетками библиотек меньше.
- C++ внутри OrcaSlicer. Ближе всего к слайсеру, но очень сложно собирать и отлаживать за короткий срок.
- Python для всей логики и простые HTML-страницы без фреймворка. Был первоначальным вариантом, заменён на React из-за сложности интерфейса с редактированием параметров (ADR-0003).
- Python для логики и React для интерфейса (выбрано). Для всех нужных задач есть готовые библиотеки, а интерфейс удобно делать на привычном для веба инструменте.

## Последствия

Плюсы:

- Вся логика на одном языке, проще разделять задачи и проверять код друг у друга.
- Граница между частями чёткая (API), фронтенд и бэкенд можно делать параллельно.
- Быстрая разработка прототипа.

Минусы:

- Появляется второй язык и второй набор инструментов (Node.js, менеджер пакетов). Участникам, которые занимаются интерфейсом, нужно знать JavaScript/TypeScript.
- Для тяжёлых расчётов на сложных моделях Python может быть медленным. Для 3-5 тестовых моделей это не должно быть проблемой, но на больших файлах проверим.
- Нужно следить за версиями библиотек: фиксируем их в файлах зависимостей (для Python и для фронтенда отдельно).
