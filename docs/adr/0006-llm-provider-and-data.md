# ADR-0006: Используем одну нейросеть (Alice AI LLM) у одного провайдера (Яндекс), файл модели ей не отправляем

- Статус: Принято
- Дата: 2026-11-12
- Уточнено: 2026-11-19

## Контекст

В ТЗ есть два требования, которые влияют на выбор нейросети:

- кейс связан с технологическим суверенитетом, то есть нужен доступный отечественный контур;
- для пилота действует условие: нет передачи чувствительных данных без контроля. Заказчик будет давать обезличенные модели.

Что требуется от нейросети в нашей системе (ADR-0004, ADR-0005):

1. Вызывать инструменты MCP (function calling) в правильном порядке.
2. Выдавать структурированный JSON с параметрами (ADR-0007), который проходит проверку без правок.
3. Сопоставлять таблицу чисел и комментарий пользователя на русском языке.
4. Писать понятное объяснение на русском.

Мы отправляем только текст (таблица чисел, принтер, материал, цель печати, комментарий), поэтому большое окно контекста и работа с изображениями не нужны.

## Решение

1. **Провайдер один: Яндекс, платформа Yandex AI Studio.** Доступ по API-ключу, формат запросов совместим с OpenAI (сообщения, список инструментов, JSON-ответ).
2. **Нейросеть одна: Alice AI LLM** (флагманская текстовая модель семейства Alice AI). Другие модели в проекте не используем: ни резервных, ни для сравнения.
3. **Обращения к нейросети идут через один небольшой модуль** (`aislice.agent.llm`). Это не для переключения между провайдерами, а чтобы весь код общения с моделью (формат запросов, повторные попытки, разбор ответа, ограничение числа шагов агента) был в одном месте и его можно было проверять отдельно. Настройки (`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`, идентификатор каталога) лежат в `.env` на сервере. Пользователь ключ не вводит, в браузер он не попадает.
4. **Наружу уходит только текст.** Числа из анализа (ADR-0005), выбранный принтер и материал, цель печати, комментарий пользователя и результаты инструментов. Сам файл модели, его геометрия и изображения не отправляются.

## Что известно о модели

Сведения взяты из открытых источников на ноябрь 2026 и частично из заявлений самого Яндекса. Тестов именно по нашей задаче у нас пока нет.

- Alice AI LLM представлена в семействе Alice AI вместе с моделью для изображений (VLM) и моделью для генерации картинок. Она пришла на смену линейке YandexGPT.
- По заявлению Яндекса, модель в 60% случаев превосходит DeepSeek V3.1 и Qwen3-235B на бизнес-задачах, особенно при ответах по документам, написании и редактировании текстов. Это данные производителя, независимой проверки мы не видели.
- Сильные стороны, о которых заявляет Яндекс: краткие и чёткие ответы, точное извлечение данных из документов, поиск информации. Для нас это означает хорошую работу с таблицей чисел и короткие понятные пояснения на русском.
- Модель работает только в облаке Яндекса, локально её не запустить. Это важное ограничение (см. "Последствия").
- В сторонних каталогах указано окно контекста порядка 32 тысяч токенов. Нам хватает: таблица анализа и профиль занимают несколько тысяч токенов.

**Что нужно проверить в первую неделю (до того, как строить остальное на этой модели):**

- Поддерживает ли Alice AI LLM в нашем API-доступе вызов функций (инструментов) в стиле OpenAI и принудительный JSON-ответ; если нет, проверить запасной способ: просить модель вернуть JSON по схеме и разбирать его самим.
- Умеет ли она вызывать несколько инструментов подряд и держать порядок `inspect_model` -> `analyze_orientations` -> `get_profile` -> `set_parameters` -> `slice_model` -> `check_result` (ADR-0004).
- Точное название и идентификатор модели в каталоге Yandex AI Studio, условия доступа, лимиты, цена. Эти данные меняются, поэтому берём их из актуальной документации Яндекса, а не из этого ADR.
- Где хранятся и обрабатываются запросы, как относится Яндекс к использованию данных клиентов (для пункта ТЗ о контроле данных).

## Как проверяем качество

На 3-5 тестовых моделях (ADR-0011), включая П-образную деталь, прогоняем модель с одинаковым набором инструментов и считаем:

- долю прогонов, где инструменты вызваны в правильном порядке без подсказок;
- долю ответов, прошедших проверку JSON без правки;
- совпадение выбранного положения с выбором инженера;
- качество объяснения: ссылки на числа из таблицы, понятность (короткая ручная оценка);
- время ответа и стоимость одного запуска.

Если результаты окажутся недостаточными, это повод написать новый ADR о смене модели или провайдера, а не молча подменять её в коде.

## Рассмотренные варианты

- Использовать несколько провайдеров (GigaChat, Yandex и локальные модели) с сравнением. Даёт запасной вариант и возможность выбрать лучшую модель, но удваивает объём проверок и настройки, а у команды мало времени. Отклонено; вернёмся к этому, если Alice AI не пройдёт проверку.
- Локальная открытая модель. Данные остаются внутри, но нужно оборудование, и качество на старте может быть ниже. Не выбрано для MVP.
- Зарубежная облачная модель. Лучшее качество, но не проходит по требованию суверенитета и контроля данных.
- Отправлять в нейросеть сам файл модели или её изображения. Лишний риск для данных и не нужно, потому что геометрию считает код (ADR-0005).
- Одна нейросеть Alice AI LLM у одного провайдера (Яндекс), отправка только текстового описания (выбрано). Отечественный облачный сервис, одна настройка, меньше работы на проверку.

## Последствия

Плюсы:

- Выполняется требование ТЗ про отечественный контур.
- Одна модель и один провайдер: проще писать, тестировать и объяснять на защите; описания инструментов настраиваем под одну модель.
- Данные заказчика остаются под контролем: наружу уходит только текст, геометрия остаётся на компьютере.

Минусы и риски:

- Зависимость от одного провайдера: если доступ, цена или качество изменятся, придётся менять модель и перепроверять описания инструментов.
- Модель работает только в облаке. Если заказчик потребует полностью замкнутый контур без внешних запросов, придётся писать новый ADR и искать другую (локальную) модель.
- Не подтверждено, что вызов функций работает так, как нужно нашему сценарию (см. проверку в первую неделю). При проблемах понадобится запасной способ управления агентом через JSON.
- Ключ API и доступ к платформе нужно получить заранее (регистрация, возможна верификация организации).
- Данные о моделях, ценах и лимитах меняются; перед пилотом проверяем актуальные условия на сайте Yandex AI Studio.
